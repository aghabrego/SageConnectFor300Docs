Capítulo 04 · Web Screen

Configuración del Web Screen paso a paso

Antes de ejecutar Sage Connect for 300 es indispensable contar con el Web API de Sage 300 publicado en IIS. Esta guía recorre, paso a paso, el despliegue local y la verificación del endpoint que utiliza el conector.

§ 01 ¿Qué es el Web Screen?

El Web API de Sage 300 —conocido como Web Screen— es el servicio HTTP publicado bajo IIS que expone los datos del ERP (customers, invoices, accounts, etc.) para ser consumidos por aplicaciones externas. Sage Connect for 300 lo utiliza como origen de datos durante la sincronización.

Su URL por defecto, una vez instalado, es: 

http://localhost/Sage300WebApi/v1.0/<compañia>/<módulo>/<recurso>

Por ejemplo, una consulta de clientes en la compañía SAMLTD se vería así: 

GET http://localhost/Sage300WebApi/v1.0/SAMLTD/ar/customers

§ 02 Prerrequisitos

Antes de instalar el Web API, asegúrate de contar con lo siguiente en el equipo donde correrá:

  • Windows 10 / 11 o Windows Server 2016 o superior.
  • IIS instalado y habilitado, con el rol Application Development activado.
  • .NET Framework 4.7.2 o superior.
  • Sage 300 instalado y con al menos una compañía configurada y operativa.
  • SQL Server accesible y con las bases de datos de Sage 300 registradas.
  • Una cuenta de Windows con permisos de db_datareader y db_datawriter sobre las bases de Sage 300 (o un usuario SQL equivalente).
  • El instalador del Web API de Sage 300, localizado en los medios originales de instalación bajo la carpeta WebAPI.
Sugerencia. Si vas a publicar el API en un servidor remoto, replica los mismos requisitos en ese equipo y abre el puerto 80/443 en el firewall. Esta guía se enfoca en localhost, que es el escenario típico de Sage Connect.

§ 03 Instalar el Web API

  1. Ejecuta el instalador setup.exe del componente Web API desde los medios de Sage 300.
  2. Acepta los términos de licencia y haz clic en Siguiente.
  3. Selecciona el sitio IIS destino. El valor por defecto (Default Web Site) es suficiente para localhost.
  4. Define la ruta virtual de la aplicación. Por defecto es Sage300WebApi; consérvala para que coincida con la URL esperada por Sage Connect for 300.
  5. Completa el asistente. Al finalizar se habrán creado:
    • El Application Pool Sage300AppPool.
    • La aplicación virtual Sage300WebApi dentro de Default Web Site.

§ 04 Configurar el Application Pool

El instalador crea el AppPool con la identidad ApplicationPoolIdentity, que normalmente no tiene acceso a SQL Server. Ajusta su identidad para que pueda leer las bases de Sage 300:

  1. Abre el Administrador de IIS (inetmgr.exe).
  2. En el árbol izquierdo, selecciona Application Pools.
  3. Selecciona Sage300AppPool y haz clic en Advanced Settings….
  4. En la propiedad Identity, elige una cuenta que tenga acceso a SQL Server (por ejemplo, IIS AppPool\Sage300AppPool o una cuenta de dominio específica).
  5. Haz clic en OK y reinicia el AppPool.

§ 05 Configurar credenciales y compañía

El Web API lee sus credenciales y la compañía por defecto desde un archivo de configuración publicado por el instalador. Ubícalo dentro de la carpeta de la aplicación virtual (típicamente %SystemDrive%\inetpub\wwwroot\Sage300WebApi) y edítalo: 

{
  "Sage300": {
    "Company": "SAMLTD",
    "User":     "ADMIN",
    "Password": "********",
    "Language": "es"
  },
  "ConnectionStrings": {
    "Default": "Server=TU_SERVIDOR;Database=SAMLTD;Trusted_Connection=True;"
  }
}
  • Company: código de la compañía en Sage 300 (visible en la barra de título al iniciar sesión).
  • User / Password: usuario con permisos para consultar los módulos que vas a sincronizar.
  • ConnectionStrings.Default: cadena de conexión a SQL Server apuntando a la base de la compañía.
Precaución. En entornos productivos evita guardar la contraseña en texto plano. Considera cifrar la sección o usar una cuenta de servicio con autenticación integrada de Windows.

§ 06 Probar el endpoint

Desde una terminal o el navegador, ejecuta una solicitud GET contra un recurso básico. Una respuesta JSON confirma que el Web API quedó correctamente publicado: 

curl http://localhost/Sage300WebApi/v1.0/SAMLTD/ar/customers?limit=5

Resultados esperados

CódigoSignificadoAcción recomendada
200 OK El endpoint responde con datos JSON. Continuar con el siguiente capítulo.
401 / 403 Credenciales rechazadas o permisos insuficientes. Revisar usuario/contraseña y permisos del AppPool en SQL.
404 La ruta virtual no está registrada. Verificar que la app Sage300WebApi exista en IIS.
500 Error interno del Web API. Revisar el visor de eventos y los logs de IIS.

§ 07 Conectar Sage Connect for 300

Una vez que el Web API responde en http://localhost/Sage300WebApi/v1.0, configura el conector para que apunte a esa misma URL. Edita el archivo appsettings.json que reside junto al ejecutable del Manager: 

{
  "Sage300": {
    "BaseUrl":    "http://localhost/Sage300WebApi/v1.0",
    "Company":    "SAMLTD",
    "User":       "ADMIN",
    "Password":   "********",
    "Timeout":    60
  }
}

El campo BaseUrl debe coincidir exactamente con la ruta publicada por IIS. Cualquier diferencia (mayúsculas, slash final, protocolo) impedirá la sincronización.

§ 08 Errores frecuentes y solución

404 — La ruta no existe

Significa que el Web API no está publicado. Abre IIS y verifica que la aplicación virtual Sage300WebApi esté presente bajo Default Web Site.

401 / 403 — Acceso denegado

Revisa dos cosas: las credenciales en el archivo de configuración del Web API y la identidad del Sage300AppPool. Esta última debe tener acceso a SQL Server.

500 — Error interno

Consulta el Visor de eventos de Windows bajo Application y los logs de IIS en %SystemDrive%\inetpub\logs\LogFiles. Normalmente apunta a una cadena de conexión mal formada o un módulo de Sage 300 no licenciado.

Timeout al sincronizar

La primera carga de catálogos puede tardar varios minutos. Aumenta el valor de Sage300.Timeout en appsettings.json o espera a que la compañía termine su rutina de mantenimiento.

Listo. Con el Web API respondiendo 200 OK y el appsettings.json apuntando a esa misma URL, Sage Connect for 300 ya puede iniciar la primera sincronización manual descrita en el capítulo de Configuración.
